# Library: correct records, unusable product

## What happened

The Raindrop import preserved 895 bookmarks, 260 highlights, notes, tags,
collection paths and original checksums. Export round-trips and agent search
passed. Opening the resulting Library was not part of that verification.

The console loaded every source, then each head, link list and linked original
separately before rendering. The imported records implied at least 2,687 D1
calls on that path. Filters ran afterward. Lazy thumbnails did not bound those
reads or the rendered cards. The exact production exception was not captured;
the query count does not establish whether a database limit, rendering CPU,
payload size or another failure caused the observed outage.

The interface exposed tables rather than jobs: assets, sources, revisions,
identifiers, import receipts and links. It repeated import metadata in tags,
notes and file controls. Every card carried configuration and destruction
controls before the reader chose an item. An internal JSON receipt looked like
a document to read. Related reference images appeared as unrelated files.

A supported PDF was refused because its long filename had no extension even
though its recorded MIME type was `application/pdf`. Tests used short names
ending in `.pdf`. The UI offered a processing action without checking the
same eligibility rule, then reported an unsupported format after a click.

## Why the existing rules did not catch it

ADRs settled ownership, immutable originals, revision conflicts, projections
and processing budgets. Those decisions were necessary, but they did not
specify a useful default Library or a bounded browse request. Component rules
settled field, colour and interaction mechanics; assembling compliant pieces
did not make the whole screen understandable.

Tests largely reproduced the implementation's nouns and buttons. A test that
checks five adjacent actions can preserve clutter just as effectively as it
preserves functionality. Small fixtures missed the cost model. Synthetic
five-format extraction established provider integration, not compatibility
with existing filenames or a usable processing journey. A deployment smoke
check covered health, CSS and MCP—not the owner's populated Library.

The failure was an acceptance gap, not a shortage of components or another
reason to add an abstraction. The import owner should have opened the actual
populated view before declaring the import usable. Release evidence should
have distinguished data integrity, retrieval, screen usability and scale.

## Interaction contract

The primary job is to find and open a saved page or document. Browsing comes
before adding, linking, processing configuration or deletion. A card needs a
recognizable title/thumbnail, source or file type, one concise description,
and organization labels in a predictable place. Internal ids and revision
counters are not primary reading information.

Originals, authored notes, import provenance and generated suggestions remain
different data. Presentation may hide repetitive import bookkeeping; it must
not delete or rewrite it. Import receipts belong with import details, and
related reference images group by written project/reference labels rather
than a guessed relationship. Archive hides an item reversibly; permanent
delete removes it; unlink only removes a relationship. State those effects
where each action is taken.

File eligibility uses MIME type and filename together. Unsupported and
oversize files state their limitation before a disabled action, not after a
misleading working state. Processing and suggestion review stay beside the
Library in the existing pane, with normal links/forms as the no-script floor.
Nothing silently sends existing private files to a provider during review.

## Development and release changes

For a user-facing feature, record its user job, default populated view,
primary action, secondary/disclosed information, supported and refused states,
data-loading budget and proof boundary before building the screen. Amend the
owning ADR when that contract changes. A backend schema is not that contract.

Derive tests from those jobs, not from the current DOM. Cover a realistic
populated collection, a match outside the first window, actual metadata
variants such as missing extensions, failures before/after admission, mobile
and keyboard use, and the no-script fallback. Assert both what is visible and
what should not clutter the default view. Measure server query count and
response size independently of lazy browser resources.

Before a ready PR, walk through the feature with representative non-private
content and capture the default view and its primary interaction. Record
which claims are backed by runtime tests, real browser interaction, provider
evidence and production observation. Full verification remains mandatory;
a green suite cannot substitute for that walkthrough. The PR template and
`AGENTS.md` make this contract part of subsequent feature work.

## Evidence boundary

PR #185 provides the bounded-loading repair and 895-linked-source regressions
with scripting on and off. It does not claim the wider redesign or PDF repair
was included. The follow-up release records its own exact-head verification,
screenshots and remaining limitations. No unread private document or broad
semantic-quality claim is used to fill a missing proof.
