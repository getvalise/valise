# 0003. MCP tool surface: eleven typed tools, two doors for skills, no generic writes

Date: 2026-10-12
Status: accepted
Amended: 2026-10-20 by ADR-0015, planning five asset/source tools; implementation remains pending.

## Context

Valise serves several client families with different capabilities. ChatGPT Deep Research only retrieves through a `search` + `fetch` tool pair. Most clients discover capability through tool descriptions, since almost none implement SEP-2640 natively yet (see the research doc's client matrix). The CSS vibe garden project established the house rule that hard constraints live in the tool surface, not in prompt text.

## Decision

The v1 MCP surface is exactly the eleven tools in the spec table: `search`, `fetch`, `create_todo`, `list_ready`, `claim_todo`, `update_todo`, `complete_todo`, `save_memory`, `list_skills`, `get_skill`, `publish_skill`. Frozen as the v1 contract; additions need a new ADR, removals need a deprecation note in the changelog.

Rules the surface encodes rather than asks for:

- No generic write tool and no delete tool. Deletion is UI-only in v1. Memory edits create revisions. An agent cannot express an destructive operation the product forbids.
- `search` and `fetch` follow ChatGPT's Deep Research contract (ranked snippets with ids; full item by id) so one implementation serves both the richest and the most constrained client.
- Mutating to-do tools require the fencing token while a claim is active. A stale token returns a tool error naming the current holder, so the model self-repairs instead of corrupting state.
- `save_memory` requires type and tags in the schema. Classification happens at write time by the agent that has the context, not by a server-side model (classification is deferred to v2 per the research doc).
- `publish_skill` validation failures return as `is_error` tool results listing the specific violations, the vibe garden repair-loop pattern.
- Skills are served through two doors with one source: the tool pair (`list_skills` cheap, `get_skill` full) for today's clients, and SEP-2640 `skill://` resources (`skills/list`, `skills/get`) for clients that adopt the extension.
- Tool descriptions are written for the model and state when to call, since description text is the only discovery mechanism in fallback clients.

## Consequences

Gained: one surface works from Claude Code, claude.ai (web and mobile), ChatGPT dev mode, Cursor, and Gemini CLI without per-client variants; destructive mistakes are unrepresentable rather than discouraged. Given up: agents cannot delete or bulk-edit, which pushes occasional cleanup to the UI. Inherited: every new tool is a contract change with an ADR, which is friction by design.
