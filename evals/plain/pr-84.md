You can now ask an agent to change what your hooks say ("start every session with a reminder to write British spelling", "take out the custom Stop line about tests"). Until now that needed the console's Hooks page. The change reaches every machine whose hook holds a `config:read` token, within ten minutes, the same as a console edit.

## What changes

- New tool `list_hooks`, scope `config:read`. It returns every entry with its id, event, text, enabled, every_turns, and shipped default.
- New tool `edit_hook`, scope `config:write`, one entry per call. `action` is `add`, `change`, or `remove`, with optional `id`, `event`, `text`, `enabled`, and `every_turns`. It applies `editHookConfig` from `app/concepts/hook-config.ts`, the function the console uses, so the 2000/8000 limits and the "A shipped entry can only be off." refusal are the same. A missing field is named the way a missing required field is ("Missing or invalid: text.").
- `every_turns` is ignored for a SessionStart entry. The OpenAI models fill every optional field and sent `every_turns: 1` when they changed `recall-reminder`, which the console's edit would refuse.
- New scope `config:write` in `MCP_SCOPES`, with a consent sentence. It is stored in `bearer_token_grants`, so there is no migration.

## The decision to review

ADR-0004 said "There is no `config:write`". This PR amends that line. Consent grants the whole scope vocabulary, so every OAuth client gets `config:write` the next time it consents. A connected agent can then change text that is injected into every future session. That is the same trust as a write to `~/.valise/config.json`, which `clients/valise/README.md` already describes under "Trust". Each change is logged as an `edit_hook` call on the logs tab and shows on `/hooks`. If that is too wide, the narrower option is to keep `config:write` out of the consent grant so that only console-minted tokens hold it. Agents connected through OAuth would then not get `edit_hook` at all.
