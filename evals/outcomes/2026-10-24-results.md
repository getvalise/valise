origin/main. It predates library and tenant work and is not a current-main
baseline. Candidate `9541483` is an orientation branch checkpoint, run from an
isolated detached checkout. These historical results cannot isolate the
orientation change and do not prove a deploy. Neither existing feature branch
was edited. The corrected comparison uses fetched main `831d843` and its
descendant orientation candidate `35b8cf9`, documented separately.

Mini finds `list_todos` on the candidate but repeatedly invents optional cursor
values: `.`, whitespace, `0`, `!`, and a fabricated base64 object. The server
rejects them. Selecting the right tool does not recover the completed tasks.
Some reminder episodes also convert the explicit ISO start incorrectly.
The zero-model `candidate-valid-cursor-control.json` shows that omitting cursor
returns the two included completions and the upper-boundary task, whose
`completed_at` correctly excludes it from the user's half-open interval.

Partial-work failures select the blocked deployment task or answer
`resume_impl` without fetching the earlier agent's progress. Correct direct-ID
answers demonstrate that the persisted `integration-check` evidence is
available. The shipped reminder repeatedly adds a skill-list call and searches
on arithmetic; these are actual calls to the 64-skill catalog, not canned
results. Correct algorithm answers often use adequate search snippets without
a full fetch; version 2 records source-fetch coverage separately from success.

A targeted Haiku candidate diagnostic, one sample per arm on resumption and
completion, passes 3/4 for $0.0258. Both completion cases pass in one tool call;
the reminder resumption passes in seven calls. Hookless resumption caps after
eight calls and misses the blocker. This is evidence the fixtures can be
answered through the candidate API, not a cross-model improvement estimate.
